# 五块蓝图

原则：**只拿小行星的设计，不拿它的代码**。它是按"后端 + 网络"长出来的，
我们要的是装在一台手机里、自己能跑完的东西。

---

## 一、上下文

**从小行星拿什么**
- 发模型前的上下文由**一个地方**组装（它的 `chat.build_context`），前端一概不管。
- 思考链不进上下文（要展示的另存一份）。
- 工具结果超限就裁；工具结果**可以被摘要替换**（这套设计是对的）。
- 按轮压缩：挑连续几轮压成一条系统摘要，原文真删，不是"只改 AI 看到的"。

**它踩过的坑**
- 前后端字段对不上，前端靠 `uuid`、`date|time|content` 猜着匹配 → 屏幕上重复 20 张工具卡，
  库里其实只有一份。它的文档自己承认了。
- 一次工具调用在历史里是**两条**（assistant 带 tool_calls + tool 结果），
  前端不知道这条规则，就会把"一对"当成"重复"。

**我们怎么做**
- 上下文只有一个来源：本地库。界面只显示，不做任何"合并 / 去重 / 重排"。
- 组装写成**一个纯函数**：`buildContext(rows, settings) -> List<Message>`，不碰网络、不碰数据库，
  单测直接喂假数据。小行星这块在 1661 行的 `chat.py` 里，我们不要那样。
- 库里的行 = 模型看到的内容，一比一。任何"库里没有、只有屏幕上有"的东西都不许存在。

## 二、记忆

**从小行星拿什么（这块是它最值钱的部分）**
- 每条记忆有**短标题**（4–6 字，是"名字"不是摘要），改标题不动内容、不重算。
- 权重衰减：太久没被提起会变轻，被提起就重新亮起来。**淡 ≠ 删**。
- **重要位有限**：不参与衰减，但位子少，"重要"才有分量。
- 多路召回再合并：语义 + 字面 + 权重 + 新鲜度，宁多勿漏；可选精排。
- 情绪能消化：没消化的负面情绪带额外重量，想通了就还回去。

**它踩过的坑**
- 后端 13 个文件、`service.py` 27K、`router.py` 16K，`reembed` / `retitle` 各一个脚本，精力散在维护上。
- 两套上下文来源（`context_items` + `context_recent`）加四张表，容易不同步。
- 向量硬绑一个供应商的 API。

**我们怎么做**
- 全本地 SQLite，一张库。表四张：`memories` / `tags` / `links` / `important`（重要位单独一张，限位）。
- 检索就是一个函数：分数 = 关键词命中 + 权重 + 新鲜度 `+ 向量(可选)`。
  **不配 embedding 也必须好用**——靠 FTS5（中文 ngram）+ 权重 + 新鲜度，这条路是主路，
  向量只是加分项，不是开关。
- embedding 让用户自己填：填了走它，不填走纯记录档。界面上直说两档区别。

## 三、工具调用

**从小行星拿什么**
- 多轮循环：边想边做，一次可以调多个，按"轮"分组显示。
- 敏感操作（跑命令、写文件、删东西）**强制人工审批**再执行。
- 工具结果可折叠、可摘要（摘要改的是库里正文，真影响上下文）。

**它踩过的坑**
- 一个 `builtin.py` 64K，三十多个工具，改一个要读完一大坨。
- 审批、循环、超时全挤在 `chat.py` 里。

**我们怎么做**
- 工具先做 10 个以内（时间、日程、通知、剪贴板、文件读写、翻译、记忆读写、搜索），
  一个工具一个文件 + 声明式 schema，注册表自动收集。
- 循环上限写死（比如 6 轮），超了就停并说明原因，别无限转。
- 每个工具自带三件事：schema、执行、危险等级。危险等级驱动审批，不做隐藏白名单。

## 四、模型

**从小行星拿什么**
- `providers.py` 那套重写：多站点（名字 + base_url + api_path + key + 该站点可用模型列表），
  `active` 存当前站点和当前模型。
- base_url 兼容几种填法（已带 `/v1`、已带 `/chat/completions`），这层它写得很务实。

**它踩过的坑**
- key 存在 `providers.json` 明文文件里，靠 `.gitignore` 保命。

**我们怎么做**
- key 存 Android Keystore 加密后的本地存储，不碰明文文件。
- 先只做流式正文 + 思考链开关，多模态放 v0.2。

---

## 五、主动消息

**从小行星拿什么**
- 判断逻辑：空闲多久算空、夜间静默、连续没回就别追、给"为什么现在找你"一个理由。
- 它的实现是后端常驻进程 + WS 心跳，**这块一点都不能拿**。

**我们怎么做**
- 纯本地：`AlarmManager`（准点）+ 前台服务（保活）+ `WorkManager`（兜底），开机会重排。
- 醒来做的事：本地检索最近记忆 + 拼提示词 + 调一次用户自己的模型 → 生成的话同时写进聊天记录和通知。
- 节流：最短间隔、夜间静默、用户没回就不追。
- 必须有引导页：通知权限、自启动、电池优化白名单，不设就是白发，国产 ROM 尤其。
